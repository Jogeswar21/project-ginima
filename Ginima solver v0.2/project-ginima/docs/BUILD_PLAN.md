# Ginima implementation backlog

## Evidence and scope

This plan describes the new starter, not the inaccessible original Ginima project. Existing original SymPy usage, notebooks, tests, docs, unresolved GitHub issues, and working/broken behavior remain unknown. There are no fetched issue IDs to cite. Paths marked NEW below are proposed additions. Treat the backlog as planned work, not discovered defects in the original code.

The starter implements bounded rational determinants, explicit routing, independent algorithm verification, and tests. The stable result contract and 30-case regression corpus are now implemented in version 0.2.0. The next step is G03: a restricted expression representation before symbolic determinants.

## First milestone and immediate follow-up

M0 is the included vertical slice: JSON determinant request → parser → router → exact solver → verifier → result. Completion checks: example answer -2; rational diagonal answer 1/3; singular result 0; row-swap sign property; floats/code-like strings/oversized matrices rejected; forced verifier mismatch blocks the answer; CLI produces valid JSON and nonzero exit on failure. Local test results are in `VALIDATION.md`.

G01 result standardization and G02 are implemented: one command runs 44 tests, including all 30 curated determinant cases and result-contract checks. Input validation remains in the existing parser/engine rather than a separate Problem dataclass. README includes successful, invalid and unsupported examples. Next implement G03 with a narrow polynomial expression AST and parser tests, then G04 symbolic 2×2 determinants. Do not enable arbitrary text evaluation.

## Build order

Foundation (G01–G03) → symbolic determinants and routing (G04–G05) → calculus (G06) → function graphs (G07). Probability (G08) can follow routing without depending on calculus. Add shared verification alongside each solver (G09), then compute limits and benchmark gates (G10–G12). Use SymPy for exact algebra, standard-library unittest initially, and optional plotting/notebook dependencies only when those deliverables exist.
